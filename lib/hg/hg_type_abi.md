# The type descriptor: the contract between `hangar msg gen` and `lib/hg`

Both the generator (`tools/msggen`) and the library (`lib/hg/hg_type.h`) build to this.
Change it in both places or in neither.

```c
// hg_type.h (lib/hg), the only definitions the generated headers depend on.
enum hg_field_kind { HG_U8, HG_I8, HG_U16, HG_I16, HG_U32, HG_I32, HG_U64, HG_I64,
                     HG_F32, HG_F64, HG_CHAR };

struct hg_field {
    const char *name;        // as written in the .msg
    enum hg_field_kind kind;
    uint32_t count;          // 1 for a scalar; N for name[N]; N for char name[N]
    uint32_t offset;         // byte offset in the payload (natural alignment)
    const char *comment;     // the trailing comment, "" if none (units travel with it)
};

struct hg_type {
    const char *name;        // the .msg file's stem: "depth"
    const char *schema;      // the .msg text verbatim, comments included (goes in the header)
    uint32_t schema_bytes;
    uint64_t hash;           // FNV-1a 64 of the canonical form (below)
    uint32_t payload_bytes;  // struct size rounded up to 8
    uint32_t n_fields;
    const struct hg_field *fields;
};
```

**Canonical form** (hashed): one field per line, `type name` or `type name[N]`, single
spaces, each line ended by `\n`, nothing else: no comments, blank lines, defaults,
ranges or `@restart`. FNV-1a 64 with offset basis 0xcbf29ce484222325 and prime
0x100000001b3 over the canonical bytes. Test vector, `msg/depth.msg` as in docs/01:
canonical text `"f32 depth_m\nf32 temp_c\nf32 pressure_mbar\n"`; both sides must print
the same hash for it (the generator's test and the library's test share this file).

**Layout**: C layout of a struct with the fields in order; `char name[N]` is `char[N]`;
scalars and arrays take their natural alignment (1/2/4/8); the payload size is the
struct size rounded up to a multiple of 8. The generator emits
`_Static_assert(sizeof(struct) == payload_bytes)` and one `offsetof` assert per field, so
a compiler that disagreed with the generator would fail the build, not corrupt a topic.

**Generated header** `msg/depth.h` (from `msg/depth.msg`):

```c
// Generated by hangar msg gen from msg/depth.msg; do not edit.
// SPDX-License-Identifier: LGPL-3.0-or-later
#ifndef HG_MSG_DEPTH_H
#define HG_MSG_DEPTH_H
#include "hg_type.h"
struct depth {
    float depth_m;        // m, positive down
    float temp_c;         // degrees Celsius
    float pressure_mbar;  // mbar, absolute
};
extern const struct hg_type DEPTH_TYPE;   // defined in msg/depth.c, also generated
_Static_assert(sizeof(struct depth) == 16, "layout");
_Static_assert(offsetof(struct depth, temp_c) == 4, "layout");
#endif
```

Parameter types add, in the generated `.c`, a `struct hg_param_meta` per field (default
as text, min, max, restart flag) behind the descriptor, for `lib/hg`'s parameter code
in stage 2; the `.h` is the same as for any type. Field names are C identifiers; the
generator refuses a name that is not, a duplicate, a dotted name (dataset rows are
generated by the manager, never from a `.msg`), a name longer than 63 bytes, more than
128 fields, or a `.msg` over 3584 bytes (the header's schema field). Those are the
library's run-time parser bounds too (`HG_SCHEMA_MAX_FIELDS` 128, names under 64), so
whatever the generator accepts the library can read. Names beginning with `_` are
reserved (explicit padding members `_padN`, the manager's `_seq` row fields).
